# 受け入れテスト結果（ラクネコ比較）

事務スタッフによる受け入れテストの記録。現行ラクネコと新システムを機能単位で比較し、差異と業務影響を確認した。**原本のチェックリストは [受付システム比較表.xlsx](./受付システム比較表.xlsx)**。

## テスト完了条件
- 現在ラクネコで実際に使用している機能・運用を一通り確認する
- 各項目について、新システムで同じ業務が問題なく実施できることを確認する
- ラクネコと仕様が異なる場合は、差異の内容と業務への影響を確認する
- 仕様に差異があっても、業務上支障がないものは「許容」とする
- 業務に支障があるものや重大な不具合は「要修正」として対応する
- 上記の確認が完了し、業務上問題となる未対応事項がなくなった時点をテスト完了とする

> ゴールは「ラクネコと全く同じ仕様・操作」ではなく、**現在の受付業務が新システムでも問題なく行える状態**。

## 判定区分
- **OK**: 新旧で問題なく、現状のままでよい
- **許容**: ラクネコと仕様は異なるが、業務上問題ないため許容
- **要修正**: 業務に支障 or 重大な不具合 → 対応
- **対応済み**: 要修正のうち実装が完了したもの

## 結果サマリー

### ✅ 対応済み（要修正 → 実装完了）
| 機能 | 差異（実装前） | 対応 |
|---|---|---|
| 入退館：任意期間検索 | 固定期間のみ（本日/過去7日/過去30日） | 開始日〜終了日の**任意期間指定**を実装 |
| お知らせ表示 | 新システムに未実装（ラクネコにあり） | 管理画面で設定 → **待ち受け画面に表示**を実装 |
| 退館日時の表示 | 列表示なし（データは保持） | 入退館記録に**「退館日時」列**を追加（CSV反映） |

### 🟡 許容（業務に支障なし）
| 機能 | 差異 |
|---|---|
| 来訪予定の変更 | 変更機能なし（ラクネコも不可）。削除→再作成で対応 |
| 来訪予定の削除 | キャンセル扱いで一覧に残る（ソフト削除） |
| 招待メール送信 | カレンダー経由は自動送信、手動作成時はURL共有 |
| 通知方法 | Google Chat中心（SMS/LINE等への切替なし） |

### 🟢 新システムが優位／ラクネコに無い機能
- ダッシュボード、会議室空き確認、監査ログ、来訪日超過でのQR自動無効化

### 該当なし（同等・問題なし）
- 受付機能、担当者通知、入退館記録の基本、管理者設定の大半（ログイン/権限/受付ボタン/カスタマイズ/受付時間/通知先/設定反映）は新旧同等でOK。

## 結論
要修正3件はすべて実装済み。比較表の残差異はOK／許容のみで、**業務上問題となる未対応事項なし**。テスト完了条件を満たし、**受け入れテスト完了**。
