# AIエージェント保守 ハンズオン＆実演ガイド

各メンバーが好みのAIエージェント（Claude Code / Cursor / GitHub Copilot / Windsurf など）で、**実際に1つの変更を最後まで通す**ための実演台本＆練習用ガイドです。

- **引き継ぎ会での実演**に使えます（§1 を画面共有しながら 10分程度）。
- 会の後の**自習**にも使えます（§1 を1人でなぞる → §2 の実例を読む）。

> 前提・ルールは [`AGENTS.md`](../AGENTS.md) と [`docs/ai-agent-maintenance.md`](./ai-agent-maintenance.md) に集約。本ガイドは「理屈」ではなく「実際にやってみる」ためのものです。

---

## 0. 実演の前に（安全のための約束）

- **このシナリオは本番に影響しません。** ブランチ → PR → **プレビューURLで確認**までで止めます。**マージ（＝本番反映）はしません。**
- 実演で選ぶのは **見た目だけの小さな変更**（文言1つ）。DB・通知・認証・GAS には触れません。
- 秘密情報（`SUPABASE_SERVICE_ROLE_KEY` / OAuth secret / `INVITATION_SECRET` の値など）は**チャットにもコードにも貼らない**。
- 終わったら **PRをクローズ**して片付けます（元に戻す作業は不要）。

---

## 1. 実演シナリオ（約10分・本番に影響なし）

**お題：受付端末の待機画面の文言「画面をタップして受付を開始」を少し変えて、プレビューで見た目を確認する。**

`index.html` にある実在の表示テキストです。見た目だけの変更なので、プレビューで結果が一目でわかり、安全に元へ戻せます。

### 手順

**① エージェントに前提を読ませる（最初の一手）**

> このリポジトリは受付システム（ラクネコ代替）。まず `AGENTS.md` と `docs/maintenance-handover.md` を読んで、構成と注意点を1段落で要約して。

→ 「フロントは単一の `index.html`」「変更はブランチ→PR→プレビュー→mainマージ」「CIは無い」等を要約できればOK。**この時点で、エージェントが自動でリポジトリの前提を拾えている**ことを見せるのがポイント（Claude Codeは`CLAUDE.md`/`AGENTS.md`、Copilotは`.github/copilot-instructions.md`、Cursorは`.cursor/rules/`、Windsurfは`.windsurfrules`）。

**② 変更を指示する**

> `index.html` の受付端末・待機画面に出る「画面をタップして受付を開始」という文言を「画面にタッチして受付を開始」に変えたい。ブランチを切って変更し、PRにして。mainへ直接pushしない。影響範囲（変わる画面）と確認手順も説明して。

→ エージェントが該当箇所（`index.html` 内に2箇所あります）を見つけて置換し、ブランチ作成・コミット・PR作成まで実行できるかを見る。

**③ プレビューで確認する（品質ゲート）**

- PRのコメント欄に **Vercel の Preview URL** が出ます（`reception-system-git-<ブランチ名>-....vercel.app`）。
- そのURLを開き、**待機画面の文言が変わっている**ことを目視で確認。
- 📌 **このリポジトリはPRにCIが無いので、この「プレビュー目視」が唯一の品質ゲート**です。実演でここを強調してください。

**④ 片付け（マージはしない）**

> このPRはデモなのでマージしません。PRをクローズして、ブランチも削除して。

→ PRクローズ＋ブランチ削除で、痕跡なく終了。**本番（`reception-eureka.com`）は一切変わっていない**ことを確認して締めます。

### 実演で伝わること
- AIエージェントが**前提を自動で理解**して動く
- **ブランチ→PR→プレビュー**という安全な流れが、指示ひとつで回る
- **マージしない限り本番は変わらない**（プレビューで安心して試せる）

## 2. 実際の変更例（このセッションの実績）

引き継ぎ前に実際にAIエージェントで対応した例です。**「どんな指示で」「何が変わり」「どこで確認したか」**をそのまま参考にできます。

### 例1：招待作成で過去日を選べないようにする（入力バリデーション）
- **指示（要旨）**：「来訪日に今日より前の日付を選べてしまう。過去日はエラーにして、分かりやすいメッセージを出したい。」
- **変わった所**：`index.html`（日付入力に `min` 指定＋登録前チェック）／ `api/invitation.js`（サーバー側でも過去日を `400` で弾く）。
- **確認**：プレビューで過去日を選ぶ→エラーになる。フロントとサーバーの**両方**で弾くのがポイント（フロントだけだとAPI直叩きを防げない）。
- **学び**：入力系はフロント＋API両方で守る。日付は**JST基準**で判定する。

### 例2：入退館記録の「メモ」列を「対応者」表示に変える（表示改善）
- **指示（要旨）**：「入退館記録の使われていない『メモ』列を、実際に対応した担当者が分かる表示にしたい。」
- **変わった所**：`index.html`（表示項目に「対応者」を追加、ログ取得で対応者名をマッピング、CSV出力にも反映）。
- **確認**：プレビューで入退館記録を開き、対応者が表示される／CSVにも列が出ることを確認。
- **学び**：表示項目の変更は、**画面表示・CSV出力・既定の表示項目**の3点セットで揃える。

### 例3：会議室が「同期データなし」になった（外部連携トラブル対応）
- **指示（要旨）**：「会議室の空き状況が『同期データなし』。以前は取れていた。原因調査して直したい。」
- **切り分け**：Google Apps Script の実行ログを確認 → 受付システムへのPOSTが **405** を返していた。原因は `RECEPTION_URL` を**独自ドメイン**にしていたため（独自ドメインはリダイレクトでPOSTが405になる）。
- **直し方**：`gas/reception-calendar.gs` の `RECEPTION_URL` を **直URL（`*.vercel.app`）** に変更 → `200` で同期回復。あわせて時刻の UTC→JST 読み違いも修正。
- **学び**：外部連携（GAS・通知・OAuth）は**ログで切り分け**る。`RECEPTION_URL` は必ず直URL。詳しくは [`maintenance-handover.md`](./maintenance-handover.md) のランブック。

## 3. うまくいく指示のコツ（要点だけ）
- **目的・対象ファイル・期待結果・制約**を1回で渡す（テンプレは [`ai-agent-maintenance.md`](./ai-agent-maintenance.md) §2）。
- 一度に大きく変えない。**小さいPR**に分ける。
- 変更後は必ず「**影響範囲と確認手順**を説明して」と付け足す。
- AIの提案は鵜呑みにせず、**プレビューで目視**してからマージ。

## 4. 実演で"やらない"こと
- **マージ（本番反映）** … デモでは行わない。
- **DBの削除・全更新、通知・OAuth・GASの設定変更** … 本番影響が大きいので実演には不向き。
- **秘密情報の表示** … キーやsecretの値をチャット／コードに出さない。
